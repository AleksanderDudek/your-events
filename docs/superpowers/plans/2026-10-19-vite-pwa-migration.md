# Vite + PWA Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Next.js 16 static export with a Vite build that ships the same prerendered site plus an installable, offline-capable PWA via `vite-plugin-pwa`.

**Architecture:** React Router v8 framework mode (`ssr: false` + `prerender`) is the Vite-native equivalent of `output: 'export'` + `generateStaticParams`: route `loader`s run at build time and every event permalink is still written as real HTML. `vite-plugin-pwa` (injectManifest) generates the web manifest and a Workbox service worker; a small post-build step reshapes React Router's output into the same `out/` tree GitHub Pages serves today.

**Tech Stack:** Vite 8, React Router 8.5 (`@react-router/dev`), vite-plugin-pwa 2.0 + Workbox 7, React 19.2, MUI 7 + Emotion (SSR extraction), Vitest 4, Playwright.

## Design decisions (made up front — the user asked for the recommended option at every fork)

| Fork | Chosen | Why |
| --- | --- | --- |
| Vite framework | React Router v8 framework mode | Only mainstream Vite framework with build-time loaders + per-path prerender + `meta`, closest 1:1 to App Router. Astro would split the app into islands (shared providers break); `vite-react-ssg` is pinned to react-router 6; a bare SPA loses the 1500 prerendered SEO pages. |
| PWA integration | Plain `vite-plugin-pwa`, `strategies: 'injectManifest'`, `registerType: 'prompt'` | `@vite-pwa/remix` targets Remix v2 only. injectManifest gives explicit caching rules in a typed `src/sw.ts`; prompt avoids reloading a page under a user mid-filter. |
| What is precached | App shell only: JS, CSS, favicons, category icons, manifest, `offline.html` | 1500 event pages (≈100 KB each) must not be precached. Pages, `.data` payloads, Supabase reads and images are runtime-cached instead. Because nothing generated by prerender is precached, the SW can be built at the normal client `closeBundle` and needs no post-prerender regeneration. |
| Offline navigation | NetworkFirst (3 s timeout) → cached copy → `offline.html` | Fresh data online; visited pages still open offline; never a browser dino page. |
| Prerender path discovery | `react-router.config.ts` → `runnerImport('src/build/prerenderPaths.ts')` | The RR config loader cannot resolve `@/` aliases (verified in a spike). Vite's `runnerImport` can, and loads `import.meta.env` the same way the app does, so path discovery reuses `eventsApi`/`slug` instead of duplicating them. |
| Env var names | `NEXT_PUBLIC_*` → `VITE_*` in code | Vite convention. GitHub secrets/vars keep their names; workflows map `VITE_X: ${{ secrets.NEXT_PUBLIC_X }}`, so no settings change is required. `deploy-prod.yml` passes **both** names until `production` is released past this change (it builds the `production` branch, still Next). |
| Base path | Read once in the configs (`VITE_BASE_PATH`, default `/your-events`); app code reads `import.meta.env.BASE_URL` | One source of truth instead of three files "kept in sync". |
| Output dir | Still `out/`, still `pnpm build` | Workflow contract unchanged — matters because `deploy-prod.yml` on `main` builds the old `production` branch until the next release. |
| URLs | Trailing slash kept (`AppLink`, canonical) | Next's `trailingSlash: true` made every internal href and canonical end in `/`; GitHub Pages 301s the slash-less form. Same URLs ship, no redirect hops. |
| 404 | SPA fallback HTML becomes `out/404.html` | GitHub Pages serves it for unknown paths; it hydrates the real router, which renders `NotFoundRedirect` — same behaviour as today. |
| Node | 24 in CI (`.nvmrc`), `engines >=22.22` | React Router 8 requires ≥22.22. Next 16 (the `production` branch) also runs on 24. |
| Lint | `eslint-config-next` → `@eslint/js` + `typescript-eslint` + `react-hooks` + `jsx-a11y` | Same rule families minus `@next/*`. |

```ts
// '' → served at the domain root; unset → the GitHub Pages project subpath.
export const DEFAULT_BASE_PATH = '/your-events';
export function resolveBasePath(raw: string | undefined): string {
  const value = raw ?? DEFAULT_BASE_PATH;
  const trimmed = value.trim().replace(/\/+$/, '');
  if (trimmed === '') return '';
  return trimmed.startsWith('/') ? trimmed : `/${trimmed}`;
}
/** Vite `base` / RR `basename` form: always with a trailing slash. */
export function toViteBase(basePath: string): string {
  return `${basePath}/`;
}
```

## Outcome (2026-10-19)

Executed in one pass. What changed against the plan, and why:

- **Prerender paths carry the trailing slash.** React Router names a page's
  loader-data file after the URL it is asked for (`/a/b/` → `/a/b/_.data`,
  `/a/b` → `/a/b.data`). Prerendered without the slash, every card click on the
  static site fetched a file that did not exist and showed the 404 page — while
  the dev server, which computes data on request, worked. Guarded by
  `src/build/sitePages.spec.ts` and `e2e-export/client-navigation.spec.ts`.
- **The events list renders client-side only** (`src/routes/city-events.tsx`).
  Prerendered, it shipped "Znaleziono 0 wydarzeń" and an empty state, and could
  not hydrate on a filtered URL. Next behaved the same way implicitly
  (`useSearchParams` under `Suspense`).
- **Page chrome moved from `Layout` into `App`/`ErrorBoundary`**, and the two
  data routes gained a pass-through `clientLoader`. Together they make a boot
  from `404.html` (an event added since the build) hydrate cleanly and end in
  `NotFoundRedirect`, instead of a hydration mismatch and a generic error.
  Guarded by `e2e-export/not-found.spec.ts`.
- **Build time 6 m 45 s → ~1 min**: `getCategories()` (one taxonomy read per
  build instead of one per page) and `prerender.concurrency: 8`.
- **Vite dev**: `optimizeDeps.entries` scans every module up front (lazy
  discovery force-reloaded pages mid-test), and the watcher ignores build
  output. A `data-hydrated` marker on `<html>` lets e2e wait for hydration,
  which is slower with unbundled dev modules than it was under Next.
- **Readable CSS-module class names** (`[name]__[local]__[hash]`), as Next had —
  the export suite identifies views by them.
- `e2e-export/paging-and-view.spec.ts` "changing the page size" had been broken
  since the sort control (2026-08-03) became the first combobox; fixed to target
  the page-size control by name.

Pre-existing, not addressed: the Mobile Chrome project of the dev e2e suite
fails the same ~16 tests it fails on `main` (desktop-oriented selectors against
the mobile header drawer / filter sheet).
